* Datalog Query Engine in Rust

** Overview

The Rust query engine resolves Datalog queries entirely in Rust, eliminating
per-clause WASM boundary crossings. A query enters as a single EDN string (or
structured JS objects) and exits as result tuples — all pattern lookups, joins,
rule expansion, and predicate filtering happen natively.

** Architecture

#+begin_src
  CLJS                         WASM boundary              Rust
  ─────                        ──────────────             ────
  (d/q query db rules args)
          │
          ▼
  queryEdn(edn, rules, inputs)  ──────────►  parse_query()
                                              parse_rules()
                                              bind_inputs()
                                              resolve_query()
                                                ├─ resolve_clause (Pattern)
                                                │    └─ PatternResolver::resolve_pattern
                                                │         └─ search_internal → PSS indexes
                                                ├─ resolve_clause (RuleCall)
                                                │    └─ solve_rule → alpha_rename → recurse
                                                ├─ resolve_clause (Predicate)
                                                │    └─ apply_predicate_filter
                                                ├─ resolve_clause (Or)
                                                │    └─ branch + sum_rel
                                                ├─ resolve_clause (Not)
                                                │    └─ resolve + subtract_rel
                                                └─ resolve_clause (And)
                                                     └─ sequential resolve
                                              project(find_vars)
                                 ◄──────────  tuples_to_js()
          │
          ▼
  result tuples (JS arrays)
#+end_src

** WASM API reference

*** =queryEdn(queryEdn: string, rulesEdn: any, inputs: any): any=

The primary entry point. Accepts standard DataScript EDN, returns
=:find=-shaped results.

#+begin_src javascript
// Relation (default) — returns array of tuples
db.queryEdn(
  '[:find ?name ?age :where [?e :name ?name] [?e :age ?age]]',
  null, null
)
// → [["Alice", 30], ["Bob", 25]]

// Scalar — returns single value or null
db.queryEdn(
  '[:find ?name . :where [1 :name ?name]]',
  null, null
)
// → "Alice"

// Collection — returns flat array
db.queryEdn(
  '[:find [?name ...] :where [_ :name ?name]]',
  null, null
)
// → ["Alice", "Bob", "Carol"]

// Tuple — returns single array or null
db.queryEdn(
  '[:find [?name ?age] :where [1 :name ?name] [1 :age ?age]]',
  null, null
)
// → ["Alice", 30]
#+end_src

*With rules and inputs:*

#+begin_src javascript
db.queryEdn(
  '[:find ?name :in $ % ?root :where (subgroup ?root ?s) [?s :name ?name]]',
  '[[(subgroup ?g ?s) [?g :group/children ?s]]'
  + ' [(subgroup ?g ?s) [?g :group/children ?x] (subgroup ?x ?s)]]',
  [["?root", 1]]
)
// → [["child_a"], ["child_b"], ["grandchild"]]
#+end_src

*** =queryClauses(clauses: Array, rules: Object, findVars: Array): Array=

Structured JS object input. Useful when the caller already has parsed clause data.

#+begin_src javascript
db.queryClauses(
  [
    {type: "rule", name: "subgroup", args: [1, "?s"]},
    {type: "pattern", pattern: ["?s", ":name", "?name", null]},
  ],
  {
    "subgroup": [
      {head: ["?g", "?s"], body: [
        {type: "pattern", pattern: ["?g", ":group/children", "?s", null]}
      ]},
      {head: ["?g", "?s"], body: [
        {type: "pattern", pattern: ["?g", ":group/children", "?x", null]},
        {type: "rule", name: "subgroup", args: ["?x", "?s"]}
      ]}
    ]
  },
  ["?name"]
)
#+end_src

Clause types:

| Type          | Fields                                | Example                                       |
|---------------+---------------------------------------+-----------------------------------------------|
| =pattern=     | =pattern: [e, a, v, tx]=              | ={type: "pattern", pattern: ["?e", ":name", "?n", null]}= |
| =rule=        | =name: string, args: [..]=            | ={type: "rule", name: "subgroup", args: ["?g", "?s"]}= |
| =predicate=   | =name: string, args: [..]=            | ={type: "predicate", name: ">", args: ["?age", 21]}= |
| =and=         | =clauses: [..]=                       | ={type: "and", clauses: [...]}=               |
| =or=          | =branches: [[..], [..]]=              | ={type: "or", branches: [[...], [...]]}=      |
| =not=         | =clauses: [..]=                       | ={type: "not", clauses: [...]}=               |

Pattern element encoding:

| JS value                 | Rust PatternEl               |
|--------------------------+------------------------------|
| ="?name"=                | =Var("?name")=               |
| ="_"= or =null=          | =Blank=                      |
| =":attr/name"=           | =Const(Keyword(attr/name))=  |
| =42=                     | =Const(Long(42))=            |
| =3.14=                   | =Const(Double(3.14))=        |
| =true= / =false=         | =Const(Bool(..))=            |
| ="hello"=                | =Const(Str("hello"))=        |

** Rust API reference

*** Query parser (=query_parser.rs=)

#+begin_src rust
use persistent_sorted_set::query_parser::*;

// Parse query
let q: ParsedQuery = parse_query("[:find ?name . :in $ % ?id :where ...]");
// q.find   → FindSpec::Scalar("?name")
// q.in_vars → ["?id"]
// q.where_clauses → Vec<Clause>

// Parse rules
let rules: Rules = parse_rules("[[(lookup ?uuid ?e) [?e :bp/uuid ?uuid]] ...]");

// Bind inputs
bind_inputs(&mut q, &[("?id", Value::Long(42))]);

// Resolve
let result = resolve_query(&db, &q.where_clauses, &rules);
let tuples = project(&result, &q.find.vars()).tuples;
#+end_src

| Predicate   | Behavior                                          |
|-------------+---------------------------------------------------|
| =number?=   | =true= for =Long=, =Double=, =Ref= values        |
| =>= / =<=   | Numeric comparison via =value_cmp=                |
| =>== / =<== | Numeric comparison (inclusive)                     |
| === / =!==  | Structural equality via =PartialEq= on =Value=    |
| =-differ?=  | At least one arg pair differs (for cycle detection)|

Unknown predicates pass through without filtering.

** Design decisions

*** Ref ↔ Long normalization

DataScript treats entity references and entity IDs as interchangeable numbers.
Two normalizations ensure joins work across ref-typed attribute boundaries:

1. *Output normalization*: =PatternResolver= converts =Ref(n)= → =Long(n)= in
   the value column, so ref values join with entity IDs from the =e= column.

2. *Search coercion*: When a pattern has =Const(Long(n))= in the value position
   and the attribute is ref-typed, the resolver searches with =Ref(n)= instead.
   This handles the case where a variable was bound as =Long(n)= from a previous
   join's entity column and is now used to match a ref value.

Together these let multi-hop ref chains like =app → module → submodule → group=
resolve correctly.

*** Depth-limited recursion

Rule expansion uses natural recursion through =resolve_clause= → =solve_rule= →
=resolve_clause= with a depth counter (max 64). This is simpler than the CLJS
explicit stack + =-differ?= guard approach, and terminates because:

1. Each level resolves clauses in context — variables get progressively bound
2. On finite data, patterns eventually return empty relations (natural base case)
3. The depth limit catches pathological cases (cyclic data)

*** Alpha-renaming

When a rule branch is expanded, internal variables (those not in the head args)
get suffixed with =__auto__N= to prevent capture between branches and recursive
invocations. Head args are substituted directly with call args, preserving
bindings from the caller's context.

*** EDN comment limitation

The =edn 0.3= crate does not support =;= comments in EDN strings. Strip
comments before passing to =parse_query= / =parse_rules= if needed.
