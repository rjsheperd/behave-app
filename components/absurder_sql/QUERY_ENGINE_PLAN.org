* Datalog Query Engine in Rust

** Overview

The Rust query engine resolves Datalog queries entirely in Rust, eliminating
per-clause WASM boundary crossings. A query enters as a single EDN string (or
structured JS objects) and exits as result tuples — all pattern lookups, joins,
rule expansion, and predicate filtering happen natively.

** Architecture

#+begin_src
  CLJS                         WASM boundary              Rust
  ─────                        ──────────────             ────
  (d/q query db rules args)
          │
          ▼
  queryEdn(edn, rules, inputs)  ──────────►  parse_query()
                                              parse_rules()
                                              bind_inputs()
                                              resolve_query()
                                                ├─ resolve_clause (Pattern)
                                                │    └─ PatternResolver::resolve_pattern
                                                │         └─ search_internal → PSS indexes
                                                ├─ resolve_clause (RuleCall)
                                                │    └─ solve_rule → alpha_rename → recurse
                                                ├─ resolve_clause (Predicate)
                                                │    └─ apply_predicate_filter
                                                ├─ resolve_clause (Or)
                                                │    └─ branch + sum_rel
                                                ├─ resolve_clause (Not)
                                                │    └─ resolve + subtract_rel
                                                └─ resolve_clause (And)
                                                     └─ sequential resolve
                                              project(find_vars)
                                 ◄──────────  tuples_to_js()
          │
          ▼
  result tuples (JS arrays)
#+end_src

** WASM API reference

*** =queryEdn(queryEdn: string, rulesEdn: any, inputs: any): any=

The primary entry point. Accepts standard DataScript EDN, returns
=:find=-shaped results.

#+begin_src javascript
// Relation (default) — returns array of tuples
db.queryEdn(
  '[:find ?name ?age :where [?e :name ?name] [?e :age ?age]]',
  null, null
)
// → [["Alice", 30], ["Bob", 25]]

// Scalar — returns single value or null
db.queryEdn(
  '[:find ?name . :where [1 :name ?name]]',
  null, null
)
// → "Alice"

// Collection — returns flat array
db.queryEdn(
  '[:find [?name ...] :where [_ :name ?name]]',
  null, null
)
// → ["Alice", "Bob", "Carol"]

// Tuple — returns single array or null
db.queryEdn(
  '[:find [?name ?age] :where [1 :name ?name] [1 :age ?age]]',
  null, null
)
// → ["Alice", 30]
#+end_src

*With rules and inputs:*

#+begin_src javascript
db.queryEdn(
  '[:find ?name :in $ % ?root :where (subgroup ?root ?s) [?s :name ?name]]',
  '[[(subgroup ?g ?s) [?g :group/children ?s]]'
  + ' [(subgroup ?g ?s) [?g :group/children ?x] (subgroup ?x ?s)]]',
  [["?root", 1]]
)
// → [["child_a"], ["child_b"], ["grandchild"]]
#+end_src

*** =queryEdnMulti(queryEdn: string, rulesEdn: string, inputs: Array, sourceName: string, sourceDb?: WasmDataScript): any=

Multi-source variant of =queryEdn=. Adds a named database source that
patterns can reference via source-prefixed clauses (e.g. =[$ws ?e :name ?n]=).

The default source =$= is the instance the method is called on. One
additional source can be provided via =sourceName= / =sourceDb=.

#+begin_src javascript
// mainDb has people with :name and :age
// wsDb has workspace members with :name and :role
const mainDb = WasmDataScript.emptyDb({":name": {}, ":age": {}});
const wsDb   = WasmDataScript.emptyDb({":name": {}, ":role": {}});
// ... transact data into both ...

// Cross-DB join: find names+ages from main where workspace has a role
mainDb.queryEdnMulti(
  '[:find ?n ?a ?role :in $ $ws :where [$ ?e :name ?n] [$ ?e :age ?a] [$ws ?w :name ?n] [$ws ?w :role ?role]]',
  '', [],
  '$ws', wsDb
)
// → [["Maksim", 45, "admin"], ["Ivan", 20, "editor"]]
#+end_src

*CLJS usage:* The =impl-rust/q= function detects =:in $ $ws= automatically
and routes through =queryEdnMulti= when a =WasmDataScript= instance is
provided as the corresponding input.

#+begin_src clojure
(impl-rust/q '[:find ?n ?role
               :in $ $ws
               :where [$ ?e :name ?n]
                      [$ws ?w :name ?n]
                      [$ws ?w :role ?role]]
             db ws-db)
#+end_src

*** =queryClauses(clauses: Array, rules: Object, findVars: Array): Array=

Structured JS object input. Useful when the caller already has parsed clause data.

#+begin_src javascript
db.queryClauses(
  [
    {type: "rule", name: "subgroup", args: [1, "?s"]},
    {type: "pattern", pattern: ["?s", ":name", "?name", null]},
  ],
  {
    "subgroup": [
      {head: ["?g", "?s"], body: [
        {type: "pattern", pattern: ["?g", ":group/children", "?s", null]}
      ]},
      {head: ["?g", "?s"], body: [
        {type: "pattern", pattern: ["?g", ":group/children", "?x", null]},
        {type: "rule", name: "subgroup", args: ["?x", "?s"]}
      ]}
    ]
  },
  ["?name"]
)
#+end_src

Clause types:

| Type          | Fields                                | Example                                       |
|---------------+---------------------------------------+-----------------------------------------------|
| =pattern=     | =pattern: [e, a, v, tx]=              | ={type: "pattern", pattern: ["?e", ":name", "?n", null]}= |
| =rule=        | =name: string, args: [..]=            | ={type: "rule", name: "subgroup", args: ["?g", "?s"]}= |
| =predicate=   | =name: string, args: [..]=            | ={type: "predicate", name: ">", args: ["?age", 21]}= |
| =and=         | =clauses: [..]=                       | ={type: "and", clauses: [...]}=               |
| =or=          | =branches: [[..], [..]]=              | ={type: "or", branches: [[...], [...]]}=      |
| =not=         | =clauses: [..]=                       | ={type: "not", clauses: [...]}=               |

Pattern element encoding:

| JS value                 | Rust PatternEl               |
|--------------------------+------------------------------|
| ="?name"=                | =Var("?name")=               |
| ="_"= or =null=          | =Blank=                      |
| =":attr/name"=           | =Const(Keyword(attr/name))=  |
| =42=                     | =Const(Long(42))=            |
| =3.14=                   | =Const(Double(3.14))=        |
| =true= / =false=         | =Const(Bool(..))=            |
| ="hello"=                | =Const(Str("hello"))=        |

*** =queryPatterns(patterns: Array, findVars: Array): Array=

Simple pattern-only queries (no rules, predicates, or compound clauses).

#+begin_src javascript
db.queryPatterns(
  [["?e", ":name", "?name", null],
   ["?e", ":age", "?age", null]],
  ["?name", "?age"]
)
// → [["Alice", 30], ["Bob", 25]]
#+end_src

*** =transact(txDataEdn: string): object=

Transact tx-data against the database. Mutates the DB in place and returns a
report with =txData=, =tempids=, and =currentTx=.

#+begin_src javascript
// Basic add
db.transact('[[:db/add 1 :name "Alice"]]')
// → { txData: [{e: 1, a: ":name", v: "Alice", tx: 536870913}],
//     tempids: {}, currentTx: 536870913 }

// Map entity with tempid
db.transact('[{:db/id -1 :name "Bob" :age 25}]')
// → { txData: [...], tempids: {"-1": 2}, currentTx: 536870914 }

// Retract entity
db.transact('[[:db/retractEntity 1]]')
// → { txData: [...retraction datoms...], tempids: {}, currentTx: 536870915 }
#+end_src

Supported operations: =:db/add=, =:db/retract= (with/without value),
=:db.fn/retractAttribute=, =:db.fn/retractEntity=, =:db/retractEntity=, map
entities, tempids, lookup refs, =:db/current-tx=, upsert, nested maps, reverse
refs. Returns ={error: "..."}= on parse or constraint errors.

** Rust API reference

*** Query parser (=query_parser.rs=)

#+begin_src rust
use persistent_sorted_set::query_parser::*;

// Parse query
let q: ParsedQuery = parse_query("[:find ?name . :in $ % ?id :where ...]");
// q.find   → FindSpec::Scalar("?name")
// q.in_vars → ["?id"]
// q.where_clauses → Vec<Clause>

// Parse rules
let rules: Rules = parse_rules("[[(lookup ?uuid ?e) [?e :bp/uuid ?uuid]] ...]");

// Bind inputs
bind_inputs(&mut q, &[("?id", Value::Long(42))]);

// Resolve
let result = resolve_query(&db, &q.where_clauses, &rules);
let tuples = project(&result, &q.find.vars()).tuples;
#+end_src

*** Built-in predicates

*Fast path (inlined):*

| Predicate     | Behavior                                          |
|---------------+---------------------------------------------------|
| =>= / =<=     | Comparison via =value_cmp=                        |
| =>== / =<==   | Comparison (inclusive)                             |
| === / ====    | Structural equality via =PartialEq= on =Value=    |
| =!== / =not== | Structural inequality                             |
| =-differ?=    | At least one arg pair differs (for cycle detection)|

*Extended (via =fn_expr::eval_fn=):*

=zero?=, =pos?=, =neg?=, =even?=, =odd?=, =true?=, =false?=, =nil?=, =some?=,
=number?=, =string?=, =keyword?=, =not=, =empty?=, =re-find=, =re-matches=,
=clojure.string/blank?=, =clojure.string/includes?=, =clojure.string/starts-with?=,
=clojure.string/ends-with?=, and all comparison/arithmetic fns.

*Database-aware (via =Clause::DbFnExpr=, access resolver):*

=get-else=, =get-some=, =missing?= — search the database per-tuple during query
evaluation. =get-else= returns found value or default; =get-some= tries attrs in
order; =missing?= filters tuples where attr exists.

Unknown predicates pass through without filtering.

** Design decisions

*** Ref ↔ Long normalization

DataScript treats entity references and entity IDs as interchangeable numbers.
Two normalizations ensure joins work across ref-typed attribute boundaries:

1. *Output normalization*: =PatternResolver= converts =Ref(n)= → =Long(n)= in
   the value column, so ref values join with entity IDs from the =e= column.

2. *Search coercion*: When a pattern has =Const(Long(n))= in the value position
   and the attribute is ref-typed, the resolver searches with =Ref(n)= instead.
   This handles the case where a variable was bound as =Long(n)= from a previous
   join's entity column and is now used to match a ref value.

Together these let multi-hop ref chains like =app → module → submodule → group=
resolve correctly.

*** Depth-limited recursion

Rule expansion uses natural recursion through =resolve_clause= → =solve_rule= →
=resolve_clause= with a depth counter (max 64). This is simpler than the CLJS
explicit stack + =-differ?= guard approach, and terminates because:

1. Each level resolves clauses in context — variables get progressively bound
2. On finite data, patterns eventually return empty relations (natural base case)
3. The depth limit catches pathological cases (cyclic data)

*** Alpha-renaming

When a rule branch is expanded, internal variables (those not in the head args)
get suffixed with =__auto__N= to prevent capture between branches and recursive
invocations. Head args are substituted directly with call args, preserving
bindings from the caller's context.

*** EDN comment limitation

The =edn 0.3= crate does not support =;= comments in EDN strings. Strip
comments before passing to =parse_query= / =parse_rules= if needed.

** Remaining work

*** DONE — CLJS integration

Completed via =src/absurder_sql/datascript/impl_rust.cljs=. Routes =d/q= through
the Rust engine for Rust-backed databases. No CLJS query fallback remains —
aggregates are handled in Rust since Phase 4.1.

*** DONE — Extended predicates (Phase 4.3)

Extended from 8 to ~40+ predicates by delegating to =fn_expr::eval_fn= from
=apply_predicate_filter=. Fast path retained for original 8 comparison predicates.
Known functions that return =None= are falsy; unknown predicates pass through.

*** DONE — fn-expr support (Phase 4.2)

Function expressions =[(str ?first " " ?last) ?result]= fully supported in Rust.
=Clause::FnExpr= variant in =relation.rs=, ~50 built-in functions in =fn_expr.rs=.
See =DATASCRIPT_RUST.org= Phase 4.2 for details.

*** DONE — Pull API

Pull-in-find (e.g. =[:find (pull ?e [*])]=) is implemented in =wasm_datascript.rs=.
Remaining pull gaps (attribute options, recursion depth) are tracked in
=DATASCRIPT_RUST.org= Phase 4.5 and 4.6.

*** DONE — Entity API (Phase 4.7)

=RustDBProxy= deftype in =impl_rust.cljs= implements =ISearch=, =IIndexAccess=,
=IDB= — delegating to Rust =WasmDataScript=. The standard CLJS =Entity= deftype
works unchanged on top. =entity= and =touch= functions provided in =impl_rust.cljs=.

*** DONE — Transact in Rust (Phase 4.8)

Implemented in =transact.rs= with =TransactableDB= trait. Supports =:db/add=,
=:db/retract=, =:db.fn/retractEntity=, =:db.fn/retractAttribute=, map entities,
tempids, upsert, lookup refs. WASM export: =.transact(ednString)=. CLJS bridge:
=transact-rust!= in =impl_rust.cljs=. 31 native tests. See =DATASCRIPT_RUST.org=
Phase 4.8 for full details.
