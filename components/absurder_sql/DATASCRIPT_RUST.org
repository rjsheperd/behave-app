WasmPSS, =equals= always false, JsStorage double-crossing the WASM

* Phase 2: WASM SQLiteStorage

** Context

Phase 1 established Rust-native datom keys and comparators, but storage
still crosses the WASM boundary twice per node (Rust → JS → CLJS → JS →
Rust) via JsStorage. Phase 2 gives Rust direct SQLite access on WASM so
that B+ tree node persistence happens entirely in Rust, eliminating the
JsStorage bridge.

*Key constraint:* =sqlite-wasm-rs= is a low-level C FFI binding
(synchronous, ~unsafe~), NOT API-compatible with =rusqlite=. The WASM
implementation must use raw ~sqlite3_*~ functions, not rusqlite's
~Connection~ / ~Statement~ types.

*Approach:* Transitional — Rust handles B+ tree node storage in SQLite
directly; CLJS metadata (schema, max-eid, max-tx, index root addresses,
tail) still stored via the existing CLJS StorageAdapter path. This keeps
the CLJS conn/transact flow unchanged while eliminating the hot-path JS
boundary crossings for node store/restore.

** 2.1 Datom binary serialization

- *New file:* =rust/persistent-sorted-set/src/datom_serde.rs=
- Shared by both native (rusqlite) and WASM (sqlite-wasm-rs) targets
- ~serialize_datom(d: &Datom) -> Vec<u8>~ and ~deserialize_datom(bytes: &[u8]) -> Datom~
- Format: ~[e:i64_le][a_type:u8][a_len:u32_le][a_bytes:utf8][v_type:u8][v_data:var][tx:i64_le]~
  - Attribute types: 0=None, 1=Keyword(no ns), 2=Keyword(with ns), 3=Str
  - Value types: 0=Nil, 1=Bool, 2=Long, 3=Double, 4=Str, 5=Keyword, 6=Ref, 7=Instant, 8=Uuid, 9=Bytes
- ~serialize_keys(keys: &[Datom]) -> Vec<u8>~ — length-prefixed concatenated datoms
- ~deserialize_keys(blob: &[u8]) -> Vec<Datom>~ — inverse
- ~serialize_addrs~ / ~deserialize_addrs~ — packed i64 LE (reuse existing pattern from =sqlite_storage.rs=)
- *Test:* Round-trip every Value variant; round-trip datoms with various attr types
- *Reuse:* Existing ~sqlite_storage.rs::{serialize_addrs, deserialize_addrs}~ pattern (promote to shared module)

** 2.2 Refactor native SQLiteStorage to use datom_serde

** DONE 4.8 Transact in Rust [HIGH]

*** Architecture

=TransactableDB= trait abstracts over =DataScriptDB= (native test) and
=WasmDataScript= (WASM production). Core transact logic lives in
=persistent-sorted-set/src/transact.rs= and is testable via =cargo test=
without WASM.

*** Transaction data types

- =TxEntity= — =Add=, =Retract=, =RetractAttribute=, =RetractEntity=, =MapEntity=
- =EntityRef= — =Eid(i64)=, =TempId(Neg|Str)=, =LookupRef(attr, val)=, =CurrentTx=
- =TxValue= — =Val(Value)=, =TempId=, =LookupRef=, =CurrentTx=, =Nested(Box<TxEntity>)=
- =TxReport= — =tx_data: Vec<Datom>=, =tempids: HashMap<TempId, i64>=, =current_tx: i64=

*** Implemented operations

- =:db/add= with cardinality enforcement (one: retract-old + add-new; many: skip duplicates)
- =:db/retract= with value (exact match, no-op if missing)
- =:db.fn/retractAttribute= / =:db/retract= without value (retract all =[e a]= datoms)
- =:db.fn/retractEntity= / =:db/retractEntity= (forward datoms + incoming refs + component cascade)
- Map entity expansion (mirrors CLJS =explode=) with reverse refs (=_parent=)
- Nested map entities (auto-allocated ref)
- Tempid resolution (negative numbers, strings) with consistent allocation
- Upsert via =:db.unique/identity= attributes
- Unique value constraint violation detection
- Lookup ref resolution in entity and value position
- =:db/current-tx= in entity and value position
- EDN tx-data parser using the =edn= crate

*** Not ported (CLJS fallback)

- =:db.fn/call= / custom transaction functions (require calling CLJS fns from Rust)
- =:db.fn/cas= / =:db/cas= (compare-and-swap — rarely used)
- Tuple attribute handling
